# 補足測試覆蓋率到 60%（Plan）

> **狀態**: 待執行（2026-05-06）
> **配套 spec**: [`2026-05-06-coverage-to-60-spec.md`](../specs/2026-05-06-coverage-to-60-spec.md)

## Context

PR1/PR2/PR3 完成後（commit `1050bdf`），全域 v8 lines coverage **19.96%**（從 18.05% 上升）。約定 60% lines、差 **40pp**、需 cover **~4400 行**。

ui primitive 全部 76 個都已測完（19+20+56），每個薄 wrapper 平均 +0.05pp、剩下無法靠 ui smoke 拉動。剩 82 個 business 元件（24,567 source lines），必須**集中火力深度測 top 20** 才能達到 60%。

User 不接受 hard gate (84.9/77.x) 排除 components zone 的算法、要看全域數字。

## Goal

`pnpm test:coverage`（v8 raw）：
- **Lines ≥ 60%**（目前 19.96% / 2202 of 11032）
- 1300+ unit tests pass
- type-check 0 errors
- lint clean
- hard gate 84.9/77.x **不退**

## Strategy

集中火力測 top 20 大 business 元件（占 untested 60% 行數），每個 deep mount + 關鍵 logic test 達 40-50% covered。剩下 60+ 中小元件不必測、已超出 60%。

切 4 phase：

```
Phase A (top 5  → +17pp, ~37%)
Phase B (top 10 → +12pp, ~49%)
Phase C (top 20 → +8pp,  ~57%)
Phase D (收尾邊界 + zone target → +3-5pp, ~60-62%)
```

## Phase D — 收尾邊界 + zone 補齊

完成條件以後 lines coverage 仍小於 60%、做這 phase：

1. 跑 `pnpm test:coverage` 開 `coverage/index.html`，找仍未 covered 的 hot path（多半在 `branches` 不在 `lines`）
2. 補 store / composable 邊界 case test（plan v2 PR3 Part B 的 `common-and-libs ≥ 95/90` 同步達成）
3. 加 1-2 個 conditional handler test（async error path、邊界）
4. branches 目標 ≥ 50%（v8 raw）

**Dispatch**: 1 subagent + supervisor。

**commit**: `test(coverage): Phase D - boundary + edge cases (+3pp, hits 60%)`

## Phase 之間的檢核點（mandatory）

每個 phase 結束 supervisor 必跑：

```bash
pnpm test:unit:run              # 必須全綠（pass count 不可比上一 phase 少）
pnpm lint                       # 0 errors
pnpm type-check                 # 0 errors
pnpm test:coverage              # 量 lines % 看是否符合 phase 目標
pnpm test:coverage:check        # hard gate 不退
```

任何一條不過 → 修或 revert 後再 commit、不放任 red 進 origin/dev。

## 風險

| 風險 | 對策 |
|---|---|
| subagent dispatch API 500 | retry up to 3 次、否則 supervisor 手寫 |
| business 元件 mount 拋錯（Pinia / Tauri / vue-i18n / async data 沒 mock）| spec 預載 mountWithPinia + 已測過的 store mock pattern；mount 失敗改 export-defined-only |
| over-aggressive assertion 失敗（class / portal / data-state）| 比照前面 fixer 模式、刪掉、保留 mount-no-throw + slot |
| coverage 提升不如預期（mount 但 conditional / event handler 沒 trigger）| spec 規定加 user interaction（trigger event、await flushPromises）|
| 遇到 source bug | 鎖 quirk、寫 follow-up commit；不修源、不擴大本 plan 範圍 |
| Phase A 結束後實測 ≪ +17pp | 暫停、檢查 lcov 看是否 mount 失敗；不要硬切 Phase B |
