# Antares2 v0.8.9

This release fixes two table features that were broken since the .NET migration,
hardens the table-structure DDL, and repairs the release/CI pipeline itself (the
v0.8.7 / v0.8.8 builds never published because CI failed at the "Install Node.js"
step). Backend-only — the renderer wire contract is unchanged.

## Fixes — broken features restored

- **Create Table now works.** The create-table form was sending `{ fields, options, … }`
  but the backend bound `columns`/`table` (which were never sent), so every create threw
  *"at least one column is required."* The DTO is reconciled to the real contract; columns
  render from the full field shape, the PRIMARY KEY comes from the indexes, and
  indexes / foreign keys / checks / table comment are applied as well.
- **Duplicate Table now works.** It was emitting `CREATE TABLE "" LIKE ""` (the source/
  destination names were never bound). Fixed — duplicating a table now creates `<name>_copy`.
- **PostgreSQL auto-increment columns** in Create Table now emit `GENERATED BY DEFAULT AS
  IDENTITY` (previously the auto-increment was silently dropped, producing a plain column).

## Backend — table DDL hardening

All table-structure DDL (CREATE / ALTER column / index / duplicate) was extracted from the
~1100-line write service into a dedicated, fully unit-tested `TableDdl` renderer
(269 .NET tests). Per-dialect SQL for MySQL/MariaDB, PostgreSQL, SQLite and SQL Server is
now locked by offline characterization tests. (SqlSugar's `DbMaintenance`/`CodeFirst` was
evaluated against the live MCP + a real-sqlite probe and deliberately not used for this
surface — it drops modifiers/defaults and mis-quotes; see
`docs/net-migration/2026-06-12-sqlsugar-conversion-outcome.md`.)

## CI / release pipeline

- **Releases build again.** CI ran pnpm 9, whose `pnpm store path` (invoked by
  `setup-node`'s pnpm cache) rejected `pnpm-workspace.yaml`, failing every build at
  "Install Node.js". CI pnpm is pinned to **11.5.3** and Node bumped to **22** (matching
  the dev toolchain).
- **macOS Intel (x64) builds dropped.** The `macos-13` Intel runner is scarce/being retired
  and hung every run `queued`. Releases now ship **Windows x64 / macOS Apple Silicon (arm64)
  / Linux x64**. Intel Mac users: use the arm64 build under Rosetta, or build from source.

## Developer workflow

Switched to a git-worktree-per-task workflow (removed the old no-worktree rule). Not
user-facing.
